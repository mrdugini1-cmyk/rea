# XGIMI Z9X HB — русский перевод v2 с редактурой

Цель: дополнить русификацию и исправить неестественные русские фразы и регистр. Исходный пакет com.android.newsettings, версия 6.03.03.14 (60303014). Присланные ресурсы и пять DEX сохранены без изменений. Полный исходный APK не передавался инструменту из-за ограничения размера; его assets, native libraries, ZIP-метаданные и подпись неизвестны.

## Готовые изменения

Сохранён перевод v1: 262 китайских строковых ресурса, 18 строковых значений в 14 файлах экранов. Дополнительно выполнены 924 изменения строковых ресурсов: 691 явная редакторская правка (включая русские общие библиотечные подписи), остальные — нормализация коротких подписей, начальных заглавных букв и терминов. Изменены три элемента массива color_mode9. Эти числа относятся к слоям изменений, не складываются как число уникальных ресурсов.

Направление проекции сверено с китайскими источниками: forward_project — настольная ОБРАТНАЯ проекция, dress_cast — настольная ПРЯМАЯ. Ресурс keystone_correction, несмотря на имя, имеет китайский смысл «калибровка фокусировки», этот смысл сохранён. Фоновые колонки не подменены настройками освещения. Технические названия, идентификаторы, адреса, JSON-команды и управляющие значения не подвергались глобальному переводу.

В коде дополнительно переведены 147 выбранных const-string в 70 классах: Wi-Fi, Bluetooth, калибровка, геометрия изображения, фильтры, уведомления об обновлении, дни недели. В верхней панели дата теперь форматируется как dd.MM.yyyy вместо yyyy年M月dd日. Форматирование протоколов/журналов дат не менялось. Для подсказки «Выход» с пиктограммой сохранён индекс вставки изображения; выбран текст с ведущим пробелом, не требующий изменения кода вставки. Места nnn для пиктограмм кнопок сохранены.

## Проверки

- Все 11214 записей таблицы ресурсов сверены; ресурсные ID, конфигурации и старые индексы глобального строкового пула сохранены.
- Манифест и существующие локализованные ресурсы побайтно совпадают с исходными. Форматные подстановки проверены.
- JADX независимо декодировал новые ресурсы без ошибок; в проверенных ресурсах по умолчанию китайских иероглифов нет. Явно выбранные китайские локали намеренно сохранены.
- DEX разобраны Baksmali, выбранные const-string изменены, затем четыре DEX собраны Smali. classes.dex остался исходным побайтно. В текстовом представлении Smali подтверждено отсутствие иных правок инструкций.
- Повторно разобраны 18491 класса четырёх пересобранных DEX. Сравнение с подготовленным Smali прошло. В 9 классах сборщик убрал избыточные явные нулевые/null статические инициализаторы — их значения по умолчанию эквивалентны. Других различий при обратном разборе нет.
- Контрольные суммы DEX Adler32/SHA-1 и размеры проверены. SHA-256 исходных и новых частей записаны.
- Сборщик полного кандидата проверен на искусственно составленном архиве из присланных частей с контрольными assets/native-файлами: посторонние данные сохраняются, другая версия отвергается, существующий выходной файл не перезаписывается. Это не тест установки полного реального APK.

Декомпиляция Java полного кода закончилась с 23 ошибками; для проверки пересборки использован полный Smali, а не повторная компиляция восстановленного Java. Выполненные проверки — статические, без загрузки на проекторе. Вшитые журналы, SDK-примеры, данные из сети, названия подключённых устройств и текст в изображениях не объявляются полностью переведёнными. Визуальная проверка строк и их длины на устройстве остаётся необходимой.

## Применение — пока не решено

Факты с устройства: uid=2000(shell), ro.debuggable=0, ro.build.type=user. Это не root; обычный adb root на этой сборке не даёт нужных прав. Наличие отдельного su или OEM-канала ещё проверяется, поэтому отсутствие любых привилегированных возможностей не утверждается.

Системное приложение имеет android.uid.system. Изменённый APK не может считаться обычным устанавливаемым обновлением: нет исходного ключа системной подписи. Amnesia также проверяет хеш назначенного settings payload — новый файл не входит в её существующий перечень. Эти проверки не изменялись. Ничего не устанавливалось, службы не запускались, системные файлы не заменялись. Подтверждённого способа применения на устройстве пока нет.

## Что лежит в пакете

- z9x-hb-ru-v2-payload.zip: 19 заменяемых файлов (resources.arsc, 14 XML экранов, четыре DEX) и манифест контрольных сумм. Не APK и не OTA.
- apply_to_original.py: локально объединяет правки с ПОЛНЫМ исходным APK пользователя; проверяет хеши всех пяти исходных DEX, манифеста и заменяемых ресурсов, сохраняет остальные entries, удаляет устаревшие v1 подписи. Старые v2/v3 APK signing blocks не сохраняются при новой упаковке. На выходе — только UNSIGNED-кандидат для анализа; выравнивание и системная установка не выполняются.
- editorial.tsv / resource-edits.json: правки формулировок; dex-edits.json: точные места строк в коде; *verification.json: результаты проверок.

Команда локальной сборки, когда понадобится полный кандидат для анализа (Python 3.9+):

    python apply_to_original.py projector-settings.apk z9x-hb-ru-v2-payload.zip --out projector-settings-ru-v2.UNSIGNED.apk

Эту команду не нужно выполнять для установки: она ничего не устанавливает и не решает проблему системной подписи. Не переименовывать payload в ota.bin и не запускать adb install для UNSIGNED-кандидата.

Контроль исходных частей привязывает правку к присланной версии. Передача исправлений в официальный канал/автору русификации или подтверждённый привилегированный механизм остаются возможными путями дальнейшей работы, не выполненными действиями. Ничего не отправлялось третьим лицам и не публиковалось в GitHub.

## Уточнение по SSH

Пользователь подтвердил init.svc.xgimi_ssh=running и xgimi.remoteDebug.on=true; command -v su ничего не вывел. Отсутствие su в PATH не доказывает отсутствие всех способов привилегированного доступа. В последнем Controller код b0.D (сверен по Smali) запускает /system/bin/ssh к root@127.0.0.1 с отдельным id_rsa и закреплённым known_hosts. e.s генерирует ключ на устройстве и хранит его в закрытом каталоге приложения files/xgimi-ssh с режимами 0700/0600. В установщике нет общего приватного ключа для подключения. Состояние running не доказывает возможность войти с компьютера; сетевое прослушивание и доступ пользователя не проверены. Содержимое приватных ключей не запрашивалось и не читалось. Для следующего шага запрошены только права /data/ssh и /data/ssh/params и фактический fingerprint.

## Фактическая прошивка и права служебного каталога

Пользователь прочитал fingerprint: XGIMI/Product_dapengfhm/goat_elegant:13/TP1A.220624.021.A1/v6.17.12:user/dev-keys. Это отдельный вариант HB, присутствующий в ветвях Amnesia; нельзя подменять его сценарием dapengse v6.16.24. /data/ssh имеет drwxrwxrwx root:root; /data/ssh/params — пустой файл root:root с правами 0600. Права каталога позволяют создавать записи, но сами по себе не подтверждают вход SSH или исполнение root-команд. Запрошена только конфигурация службы/sshd, никаких изменений авторизованных ключей или params не выполнялось.

Служба на фактическом устройстве объявлена в /vendor/etc/init/hw/init.xgimi.common.rc:80 как `service xgimi_ssh /vendor/bin/xgimi_ssh.sh`, SELinux-контекст u:r:xgimi_ssh:s0. /system/etc/ssh/sshd_config отсутствует. Это не стандартная подтверждённая конфигурация sshd; дальнейшие действия должны опираться на содержимое vendor-скрипта, которое запрошено для чтения. Запрос состояния службы не равнозначен получению доступа root.

## Временный root probe

Пользователь выполнил setprop ctl.restart xgimi_ssh с результатом 0; служба снова running. Прочитанный vendor-скрипт запускает sshd, один раз читает /data/ssh/params и запускает /system/bin/ssh с этими параметрами. Подготовлен root-probe.ps1/root-probe.sh только для точного fingerprint 6.17.12 dapengfhm и исходного пустого params root:0600. Он временно сохраняет исходный inode params, задаёт ProxyCommand для диагностического id, восстанавливает исходный params перед записью результата и повторно запускает службу с исходными параметрами. Обработчик выхода пытается восстановить params при ошибке; при чужом изменении сохраняет исходный файл в указанном каталоге и отказывается его перетирать. Выводит путь восстановления перед изменением. Авторизованные ключи, APK и mounts не меняет. Требуется непрерывное выполнение; на случай прерывания напечатан путь к исходному файлу. Проверен синтаксис sh; на проекторе probe ещё не выполнялся, исполнение PowerShell в Windows здесь не проверялось. До получения uid=0 привилегированное выполнение не подтверждено.
