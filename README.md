# TSBB04B — экспериментальный образ v4

Образ: candidates/v4-allranges-experimental/candidate-v4-allranges-experimental.bin
SHA-256: 50ce9ed4b65524c6238dc41af9c77000d1e3644f1a0345bdea709cae1c5b94d8

## Изменения

К v3 добавлены 21 положение баса SW и тылов SURR, шкала −10…+10. Расширены границы кнопок, отображение, нейтральные значения OTA/EQ и восстановление сохранённого SW. Центр остаётся с расширенной таблицей из v3. Точный шаг в dB не подтверждён.

SW_VOLUME и SURR_VOLUME действительно сохраняются главным блоком. Однако главный блок отправляет команды другому обработчику по программной I2C-шине; наличие локальных настроек не доказывает наличие здесь всей логики усиления получателя.

Новая связь: сохранённый индекс i=1…21, показание i−11, байт команды (i−6) mod 256. Ноль отправляет прежний код 5. Для показаний −5…+5 команды остаются прежними 0…10. Для новых нижних положений −10…−6 отправляются FB…FF; для верхних +6…+10 — 0B…0F. Знаковая трактовка и допустимость этих значений получателем НЕ установлены. Возможны игнорирование, ограничение или другое усиление: образ не является подтверждённым исправлением физического диапазона. Программный эксперимент не доказывает работоспособность на оборудовании.

Сохранены изменения v3: дисплей тускнеет через 50 тиков и гаснет ещё через 50 (номинально 5+5 секунд); активное приложение ARC блокирует два обнаруженных пути автоматического сна. Проверка ARC — режим 5 и ненулевой указатель приложения, а не проверка кабеля/HPD. CEC-обработчик побайтно сохранён; реальное выключение/включение телевизором не проверено. Bluetooth-имя из v3 сохранено и зависит от штатного условия OTA_NAME_UP. RF-пинг, кроссовер, Atmos и SBC не менялись.

Старые сохранённые индексы не мигрируются: прежний нейтральный индекс 6 теперь означает −5. Если штатный путь OTA не сбросит настройки, после обновления нужно вручную выставить SW, CEN и SURR в 0. Новый нейтральный индекс — 11.

## Проверки и пределы

Контроль исходного SHA-256, исходных байтов всех правок, обратимости кодирования, размеров, CRC32 контейнера/разделов и checksum XML пройден. Загрузчик, разметка, ресурсы и версия не изменены. Приём образа с прежним номером версии загрузчиком не проверен.

Ограниченный интерпретатор реальных MIPS16-инструкций проверил 42 случая кнопок/пакетов и 21 показание для каждого SW/SURR; 256 входов восстановления SW; центр — 256 входов драйвера, 42 кнопки и 21 показание; ARC — 32 сочетания условий; дисплей — команды на тиках 50/100. Это не эмуляция SoC, приёмника команд, HDMI или усилителей. Результаты: instruction-verification.json; правки и таблица команд: verification.json.

На физическом устройстве образ не проверялся. Исходный файл не изменялся, устройство не прошивалось, облачная среда не публиковалась.

## Воспроизведение

build_v4.py принимает путь к исходному официальному ota.bin и требует базовый образ v3 с проверяемым SHA-256 в указанном выше дереве candidates. Зависимости: research-v3/build_v3.py и ats2819-notes/tools/norline.py (MIT); для пересборки базовых ARC hooks нужен GNU MIPS binutils. Затем запустить check_v4.py; он использует ограниченный интерпретатор research-v3/check_v3.py и проверку дисплея research-v3/check_display_50_50.py. Полный анализ v3 приложен отдельно; его утверждение о неизменённых SW/SURR относится только к v3 и заменено настоящим описанием для v4.
